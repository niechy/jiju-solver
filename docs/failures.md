# 失败案例集

这份文档记录**被测量过、然后被否掉**的方向。它的用途是防止后来者重复烧机时，也顺便把「哪些数字不能引用」写清楚。

每条案例的格式固定：**试了什么 → 测到了什么 → 为什么失败 → 这意味着什么**。

阅读前先约定两条口径，全文通用：

- 所有数字都在**离线规则模拟器内**测得，不是真实客户端表现。
- 「诗意」「句数」都是**本局新增的增量**，不重发历史累计值；配对差 = 同一起始状态、同一局面种子跑两条臂后逐局做差的均值 ± 2×配对 SE。
- 除非特别说明，参考臂（reference）都写明了是什么。**参考臂换了，同一个改动的「提升」可以变一个量级**（见 §10）。

## 1. 假定整库都可抽

### 试了什么

最早的开源实现（[2233-123/-_wuhuihuaxia_verse](https://github.com/2233-123/-_wuhuihuaxia_verse)，本项目把它作为起点）用 `Verse_clean_updated.csv` 全量诗句库做蒙特卡洛模拟：`BayesianOptimization.py` 用 `skopt.gp_minimize` 在 7 个维度上做贝叶斯优化，`MonteCarloSimulation.py` 做统计。它的输入是「初始灵犀、初始消耗、初始诗句集、免费刷新次数」，**可抽池等于整库**。

该项目自己的 README 就把这条写在「局限」里：

> 实验预设诗句库中的所有诗句都是可收集的，且出现概率相等，这可能与实际游戏不符

这个建模假设不成立：真实可抽池是**已解锁且尚未收集**的句子，随收集单调缩小，而且解锁集合由玩家的养成进度决定，不是库的随机子集。

### 测到了什么

**（a）先看这个假设本身会把结果推到什么量级。** 该项目 README 自己列出的实测结果里（其口径为「总集句数」，包含初始句，不能与本项目的增量口径直接比）：

| 预设 | 平均集句数 | 分布上界 |
|---|---:|---|
| 单杜甫（25 灵犀 / 消耗 6） | **559.58 句** | P95 = **573 句**（=整库） |
| 杜甫·开局转 11 组韵 | 570.30 句 | P95 = 573 句 |
| 单温庭筠（15 灵犀 / 消耗 8 / 免费 4） | 228.88 句 | 最大 = 573 句 |

也就是说：在「整库可抽」下，很多预设的**期限由库的大小决定**（把 573 句全部收完），而不是由资源耗尽决定。这与真实局面完全不是同一个问题。

**（b）把合格池当回事之后，池不匹配的代价是可以量化的。** 在一个真实合格池快照（70 句）上训练出来的权重，直接搬到「假设 573 句全部解锁」的场景：

| 比较 | 局数 | 池内基线 | 池内拟合权重 | 配对差 / 约 95% 区间 |
|---|---:|---:|---:|---|
| 仅基础策略，假设全 573 句可抽 | 3000 | 54.8143 | **8.0073** | **−46.807 [−48.867, −44.747]**（t = −44.5） |

池内拟合的权重在全库场景下直接崩掉（54.8 → 8.0 句）。同一条报告的结论是：**「70 句池训练的新权重，直接用于假设 573 句都解锁的场景会严重退步」**，所以不能无条件替换权重。

反向也成立：为全库场景加了一个「独立续跑策略预评估」保护后，在 200 局全库起点上，原基础打法 57.72、自适应后续策略 58.77，配对差 **+1.05，约 95% 区间 [−0.129, 2.229]**——检测不到显著提升。

### 为什么失败：为什么「随机取子集，组比例不变」这个论证不够

最容易被提出的反驳是：**随机抽一个子集，韵组的比例在期望上是守恒的，所以池小一点只是把命中率按比例缩放而已。** 这个论证不充分，有四个独立的理由，而且每一个都有实测支撑：

1. **合格池不是随机子集。** 它由解锁进度决定（`WorldStart.Eligible`），带系统性偏差。历史研究里用到的真实局面就有三种规模：标准评估态剩 **68** 句、真实残局快照剩 **20** 句、全库最多 **572** 句。这三种是完全不同的分布形状，不是同一分布的抽样。
2. **期限（horizon）本身是内生的，不是固定的。** 小池时终止条件是「池被收完」：精确解在池 4~10 上的最优句数恰好等于池大小（V\*(句) = 4.0 / 5.0 / 6.0 / 7.0 / 8.0 / 9.0 / 10.0），即**最优线会把池收干净**；全库时终止条件是「灵犀不够」，实测跑出 54.81 句。同一个策略评价函数在两个 regime 下优化的根本不是一个东西，所以「按比例缩放命中率」这个操作没有定义。
3. **永久 +1 入场费的相对代价随剩余局长度变化。** 出韵连 2 次让 `Cost += 1` 且不可逆。在一局只剩 20 句的残局里，多付 1 灵犀可能只影响一两次决策；在能跑 50+ 句的局里，它按剩下的轮数持续计息。忽视这一点的策略在小池上过保守、在大池上过激进。
4. **池缩小还会改变判定类型的联合分布，不只是 Group1 的直方图。** 中间态/出韵取决于 `(Group1, Group3)` 的**联合**组成；而且 `DrawRound` 让单轮内可用池随每次刷新继续缩小（最多减 3/次），所以刷新后押韵命中率在一轮之内是递减的。只守 Group1 比例守恒的论证对这两件事都没有约束力。

（补充一条静态检查的反面证据：把「标准协议态」剩的 68 句按 Group1/Group2/Group3 + 诗人 + 灵犀属性做完全同类归并，只得到 **66 个类，最大类大小 2**。这个保守检查不是双模拟最小化，但它说明**不能指望靠「属性相同的句子聚合」把池形状的差异抹平**。）

### 这意味着什么

- 求解与训练的**唯一正确输入是真实合格池**，并且这个池必须随着收集而收缩。本仓库把这条做成硬约束：`WorldStart.Eligible` 为 `nil` 表示全库（只用于压力测试）；`TrainContinuation` 直接**拒绝** `spec.Eligible == nil`（「training requires an explicit pool」）。
- 任何跨池外推的结论都必须重新测。**在一个池上赢，不等于在另一个池上赢**；反过来也一样。
- 引用本章那些「全库」数字时，必须说清那是压力场景，不是部署口径。

## 2. 状态价值函数 V(s) 回归

### 试了什么

用一组粗粒度、近似线性的状态特征回归一个价值函数 `V(s)`，再用它去修正候选打分（选句加位置价值项）。统一基准 `cost8 / lingxi25 / sims5000 / seed42`，手调基线 125.76 句。

### 测到了什么

| 方向 | 思路 | 平均句数 | 相对基线 |
|---|---|---:|---:|
| 进化搜索学权重 | 进化算法自动调 13 维权重 | **149.92** | **+19.2%** |
| **状态价值函数** | **学 V(状态) 修正评分** | **138.27** | **+9.9%** |
| 刷新 EV 精确化 | 精确期望价值 + 灵犀时间价值 | 135.15 | +7.5% |
| 前瞻搜索 | 选句加位置价值 γ·V(prev) | 129.97 | +1.95% |

> 口径提示：这四个数字来自**当时的另一个模拟环境**，不能与本仓库 `World` 口径下的其他数字并列比较。它们只用于回答「哪个方向有希望」。

### 为什么失败

结论写得很直接：**纯状态价值函数在本游戏不可行**。机制是**状态分布极端偏斜**——押韵链把数据推到极端：

- **出韵≈0**：一个正常运行的策略几乎不主动出韵，所以「出韵状态」这个样本类别几乎是空的，而它恰恰是最需要价值函数纠正的那一类；
- **换组只在坏状态出现**：换组动作与「当前组枯竭/灵犀见底」高度共线，回归无法把「换组」本身的效应从「处境变坏」里分离出来；
- 结果是**回归系数的信噪比崩溃**：特征之间高度共线，且目标方差几乎全部来自少数稀有状态。

### 这意味着什么

- 用**粗粒度线性特征**学 `V(s)` 在本游戏不可行。这是对该具体方法的否定。
- 它**不**是否定一切学习型价值函数。后续研究明确写了这一点，并把方向指向「集合/图条件化的后状态价值估计」——但那个方向后来实测也没打赢（见 §5）。所以正确的读法是：**这条线至今没有正结果**。

## 3. 深度 ≥ 2 的前瞻搜索

### 试了什么

在选句时加一层前瞻：不只看即时收益，还看「这一步之后 `prev` 会变成什么」的位置价值。以及一个 width/inner 可控的两步搜索 pilot。

### 测到了什么

| 实验 | 结果 |
|---|---|
| 前瞻搜索（一层位置价值） | 129.97 句，+1.95% |
| **depth = 2** | **不优于 depth = 1** |
| 两步搜索 pilot（width/inner 档） | +1.08 句，SE 1.1113，**t = 0.972，p = 0.331**（n = 100） |

那个 +1.08 句的 pilot 在后来的研究复盘里被点名：

> The previous +1.08-verse pilot remains inconclusive and should not be relabeled as a success.

### 为什么失败

机制是**状态抽象丢失了关键变量**：第二层近似**忽略新的 `prev` 具体是哪一句**。而集句的核心动力学恰恰全在 `prev` 上——押韵/中间态/出韵的判定、相粘判定、`cur = groups[prev.Group1[0]]` 的换组阈值，全都以 `prev` 为条件。第一层把 `prev` 抹平，第二层的估计误差就被这一步放大而不是被平均掉。

换句话说：**加深一层≠更准**，前提是那一层的状态能表达决策真正依赖的东西。这里不能。

### 这意味着什么

- 「再深一层」不是廉价的正收益来源。要加深，先解决「如何表示新的 `prev` 与收缩后的池」这个表示问题。
- 反过来，这也**没有**证明「更深的规划在一切预算下都没用」：pilot 的外层样本数很小、第二层动作选择本身带噪声，这些都是合理限制，但它们是**未测量的推测，不是已测出的原因**。诚实说法是：**在当前可达的预算与表示下，测不到收益。**

## 4. 非线性概率特征

### 试了什么

保持线性核心权重不变，给打分加三个**精确计算**的非线性概率特征（在「选中候选 v 之后」的池上按组集合**并集**精确计数）：

```
p_hit(v) = 1 − C(n−r, 3) / C(n, 3)     // 下一批 3 句里至少一句与 v 押韵（超几何，精确）
p_off(v) = C(n−r−m, 3) / C(n, 3)       // 下一批全部出韵
dens(v)  = r / n                        // 剩余池中与 v 押韵的句占比
```

这里 `r` / `m` 是 `Group1` / `Group3` 交集的精确计数。它们修的正是冠军的两处近似（冠军用 `Group1[0]` 和「各组最大值」）。

### 测到了什么

关键设计是**隔离检验**：用**同一个停止规则**下开关这三个特征，只比较特征空间，不混入规则改动（两者用同一套在 mode 2 下调出的 `StopMargin` / `RefreshCostWeight`）：

| 比较（同一次运行内配对） | Δ诗意 | 2SE | t | 胜局 |
|---|---:|---:|---:|---:|
| 非线性特征**开** − **关** | **−7.54** | **21.60** | **−0.70** | 53/120 |

同时 `T5_nl_on.json` 与 `T5_nl_off.json`（三个非线性权重分别取调参值 / 取 0）**逐位完全相同**（配对差 0.00 ± 0.00，n = 80），确认在纯线性模式下它们是惰性参数。

另外还纠正了一个早期误读：最早把「非线性特征 + 原门控」在训练种子上测出的 −64 ~ −283 句读成「非线性特征有害」。那是**权重—模式错配的伪结果**——那些非线性权重是在「特征不生效的模式」下调出来的，直接搬到「特征生效的模式」里当然会破坏打分。正确的检验就是上面这一行。

### 为什么失败

因为在**同一个停止规则**下，这三个特征提供的信息已经隐含在「精确次序统计量 + 逐句打分」里了：停止规则已经在用真实的未屏蔽池和精确的期望最大值做权衡，而 `p_hit`/`dens` 是对同一件事的另一种（更粗的）表达。特征没有带来**新的**信息，只带来了新的待调参数。

### 这意味着什么

- **约束瓶颈是决策规则，不是特征空间**（至少在这个搜索预算下）。同样的线性价值函数、只把刷新换成一步最优停止，就能拿到 +54.7 ~ +56.6 诗意（§6 与 [algorithm.md](algorithm.md#4-精确一步最优停止当前默认刷新规则)）；而在规则固定时加特征，检测不到任何增益。
- 诚实边界：这个检验是在**训练种子**上做的，因为已经无增益就没有再花机时做留出验证。所以严格说法是「**未检测到增益**」，不是「已证伪」。也没有做「17 维线性权重 + 非线性项联合搜索」，所以不能宣称线性表示已到顶。

## 5. 集合条件化的后状态 critic（Deep Sets）

### 试了什么

按研究建议实现一个**集合/图条件化的后状态价值估计器**，替换掉 §2 那套粗粒度线性特征：

- **输入**：每句剩余诗句 **93 个特征**（韵组归属、平仄、诗人、奖励、诗人首收是否尚可用、本轮屏蔽、上一句、灵犀余额、入场费、免费刷新、连错标记），另加 **95 个上下文特征**；编码器是 Deep Sets 风格（先逐句 token 再池化）。
- **目标**：结算后的**未来新增句数**。选句 +1，刷新 +0，终局未来价值为 0，无折扣。
- **训练**：PyTorch 2.8.0+cu128，CUDA（RTX 4060 Laptop）。数据全部由模拟器生成，teacher 固定为 `CountStrategy`，每动作 64（后为 256）个蒙特卡洛未来。整局切分 train/dev，六个模型 v1~v6 迭代。导出 JSON 后在 Go 侧做严格可移植推理，PyTorch↔Go 最大绝对误差 4.89e-6 ~ 4.84e-6（8 个样本/模型，6/6 复核逐位一致）。
- **三种使用方式**：直接 critic；只给刷新做机会前瞻；所有动作等深前瞻。

### 测到了什么

全部为**整局新增句数**，配对、同一初始快照、同一模拟种子：

| 候选 | n | 参考臂 | 候选 | 参考 | 差 / 约 95% 区间 |
|---|---:|---|---:|---:|---|
| v1 直接 | 500 | `CountStrategy` | 27.528 | 30.402 | −2.874 [−3.989, −1.759] |
| v2 直接 | 500 | `CountStrategy` | 33.778 | 30.402 | +3.376 [2.334, 4.418] |
| v2 直接（**预留种子**） | 1000 | `CountStrategy` | 33.956 | 30.623 | +3.333 [2.588, 4.078] |
| v2 全动作深度 1，8 draws | 200 | `CountStrategy` + 128 抽样 rollout | 39.420 | 44.150 | **−4.730 [−6.114, −3.346]** |
| v2 全动作深度 1（**预留种子**） | 300 | `CountStrategy` + 128 抽样 rollout | 40.320 | 44.213 | **−3.893 [−4.988, −2.798]** |
| v3 策略迭代 pilot | 500 | `CountStrategy` | 25.160 | 30.402 | −5.242 [−6.369, −4.115] |
| v6 直接（**预留种子**） | 1000 | critic v2 | 35.891 | 34.136 | +1.755 [1.217, 2.293] |
| v6 全动作深度 1 | 300 | `CountStrategy` + 128 抽样 rollout | 42.3867 | 44.9800 | **−2.5933 [−3.7631, −1.4236]** |

其他测到的量：付费刷新 34.374（v6）vs 33.727（v2）——提升不是靠少刷；每次决策平均规划耗时 **20.36 ms vs 13.76 ms**（8 workers）——**更慢且更差**；P5/P50/P95 = 30/42/53 vs 32/44/61。

### 为什么失败

四个原因，按重要性排序：

1. **它打不过一个缩减预算的 rollout 参考臂。** 注意参考臂是 `CountStrategy` + 128 抽样 rollout，**不是**完整的在线规划器。「打赢裸启发式」远远不够——v6 相对裸启发式是 +14.405 ± 0.320（z=45），但收益几乎全部来自「加了规划器」这件事本身，learning 部分只贡献 +1.755。
2. **目标错配。** 它的价值目标是**句数**，而部署目标是**诗意优先、句数次之**。用句数 teacher 训出来的 critic 去参与一个诗意优先的决策，天然不在同一个目标上。
3. **唯一干净的正向结论也带着限定。** v6 相对 v2 的 +1.755 [1.217, 2.293]（预留种子 n=1000）是干净测量，但参考臂是**上一个实验模型**，不是发布基线。把它讲成「调参让策略变好了」就会反转结论。
4. **teacher 是固定策略，不是最优重规划。** 所有标签都描述 `CountStrategy` 的未来。更准地拟合一个固定策略**不等于**拟合最优规划；v4/v5 把 label regret 从 0.23524 降到 0.13784、根平均价值 MSE 从 3.72710 降到 2.61743，完整局直接对局**照样退步**——预测指标好并不选出更强的策略。
   （另一个数据侧发现：v4 与 v6 的**状态集完全相同**，只有标签抽样从 64 增到 256；v4/v5 更是同一次训练的两个 checkpoint。所以「v1..v6 六个候选」实际只有约 **4 次独立尝试**，选择压力被高估了一倍。）

### 一条必须一起说清的局限

**它的合格池没有被留出。** 原实验自己就承认了：

> Eligibility pools themselves were NOT held out: this is a snapshot-pool study with synthetic thinnings, not generalization proof.

而且所有 `set-*` 评测都是 `mixed=false` + 同一个快照，所以那些「1000 局」其实是**同一个状态的 1000 次抽样**；训练状态与该快照本身同分布。也就是说 §5 表里的区间只在**这一个池、这一个状态**上有效，不能外推到别的账号、别的池形状。

### 这意味着什么

**不要用学出来的 critic 替换 planner。** 如果还要继续这条线，正确的下一步顺序是：先把目标改成部署目标（诗意优先，多输出）、把 teacher 换成更强的规划器并保留 replay 覆盖、做**跨合格池**的独立验证，最后才谈架构。而在此之前，工程上的默认选择就是「用规划器，不用替代它的 critic」。

## 6. 两步最优停止

### 试了什么

一步最优停止（默认）只算「刷一次之后的期望最优分」。两步版本（`StopDepth=2`）再展开一层：刷完之后手里还握着「再刷一次」的期权。见 [algorithm.md](algorithm.md#5-两步最优停止stopdepth2已实现非默认) 的推导：`V₂ = Emax(P) + E[(K − maxS)⁺]`。

### 测到了什么

参考臂是一步（`StopDepth=0`），候选臂是两步（`StopDepth=2`），其余完全相同：

| 种子 | n | 诗意（一步 → 两步） | 配对差 | 2SE | t | 句数差 | 付费刷新 |
|---|---:|---|---:|---:|---:|---:|---|
| 42 | 200 | 533.100 → 550.525 | +17.425 | 16.810 | +2.07 | +1.710 | 28.460 → 35.040（+23.1%） |
| 202609401 | 200 | 550.350 → 558.525 | +8.175 | 15.890 | +1.03 | +0.695 | 29.900 → 34.975（+17.0%） |
| 两种子合并 | 400 | — | **+12.80** | 11.56 | **+2.21** | +1.202 | 约 **+20%** |

（按两个种子的效应量做反方差加权得到 **+12.54，t ≈ 2.17**；池化口径为 +12.80 ± 11.56，t = 2.21。两种算法同向。）

### 为什么没被采纳

1. **效应量本身不足以定论。** 两个种子都是正的，方向一致，但 **t ≈ 2.17、只有两个种子**。在做了很多次比较的语境下（§10），一个孤立的 t≈2 结果不应该被相信。
2. **付费刷新被抬高约 20%**，而其中一部分来自**已知的近似**：`K` 里「再刷时的池」被当成 `P` 本身，实际它应该是 `P` 减去刚展示的 k 句。这个近似的方向是**高估**期权价值，于是策略比应该的更爱刷。也就是说，观测到的 +12.8 里混进了「近似误差带来的额外刷新」的贡献，无法与真实期权价值分离。

### 这意味着什么

- 代码保留 `StopDepth`（数学上是严格推广：`V₂ ≥ Emax(P)`，期权价值非负），但**默认置 0**，并把这个选择写进权重注释。
- 要把它转正，需要：修掉 `K` 的池近似（改成 `P \ 刚展示的 k 句`）、加种子数、以及确认「多花的 20% 付费刷新」在低灵犀状态下不会烧掉连锁的最后一口气。

## 7. 动作条件策略筛选 / 终局修复 / 两步搜索

三类「在既定规划器上加一层」的实验，全部**默认关闭**，全部未测到增益。

### 测到了什么

|---|---|---:|---|---:|---|
| **终局修复**（`TerminalPolicy`） | 当刷新非法、且每个合法选句的 `AfterState` 都终局时，改按目标直接挑即时向量回报最好的一步 | 200 混合 / 202609208 | 380.225 → 379.175，**−1.05 [−4.8952, 2.7952]** | **−0.145** | t = −0.724，p = 0.469 |
| **动作条件策略筛选**（`ActionPolicies`，当前 refine 模式） | 保留全局筛选，再为每个强制根动作独立精炼一条续跑策略 | 200 混合 / 202609210 | 373.675 → 368.975，**−4.70 [−14.0684, 4.6684]** | −0.375 | t = −0.848，p = 0.397 |
| 同上（早期被弃的 replacement 变体，8 样本） | 取消了全局筛选，因此同时改变了不确定性回退 | 200 混合 / 202609209 | 380.550 → 369.425，−11.125 [−21.8156, −0.4344] | −1.385 | t = −2.596，p = 0.009 |
| 同上（replacement 变体，32 样本） | 同上（同种子消融，**不是独立确认**） | 200 混合 / 202609209 | 380.550 → 382.225，+1.675 [−8.1357, 11.4857] | +0.06 | t = 0.125，p = 0.900 |

被问到的另外两个「−0.51 / +0.96」的句数差，出处是同一批评测里的另外两行，标签容易串，这里一并给出，避免误引：

| 文件 / 实验 | n / 种子 | Δ句数 | t / p |
|---|---:|---:|---|
| Shiyi 目标筛选 + 精确残局 vs count 目标 rollout | 200 / 202609202 | **−0.51** | t = −0.705，p = 0.481 |

### 为什么失败

1. **修复只作用在「已经没有未来」的那一步。** 终局修复在局部是可证的（同一 fixture 上句数不变、诗意从不下降、部分严格变好），但**局部支配不蕴含整局收益**：当每个合法动作都会终止本局时，这一层的策略代理已经没有未来价值，改它只能改最后一步的零头。而且它更贵——每次决策平均规划耗时 18.62 → 24.09 ms。
2. **动作条件的策略精炼把计算花在了错误的地方。** 它为每个根动作单独筛一条续跑策略，计算量大约翻倍（12.93 → 26.39 ms），而根动作只有至多 4 个、且每个动作的续跑策略在给定状态下差别很小。更关键的是：它**不是**一个干净的隔离实验——被弃的 replacement 变体连全局筛选和不确定性回退一起换掉了，所以那两行（含显著的 −1.385 与不显著的 +0.06）都不能读成「续跑质量」的效应。
3. **两步搜索在预算内被噪声吃掉。** 外层样本数小，第二层动作选择本身带噪；收益还没出现，方差已经先到。这条**不**证明「更深的搜索在所有预算下都没用」（原报告也是这么写的）——但它证明**在这个预算、这个设计下没有**。

### 这意味着什么

- 三个开关都保留、都 `OFF`，并且在线路径 `planLive` **显式拒绝**它们。这是「未证明的改动不得进入默认路径」的落地方式。
- 想继续这条线，优先级不是「把这个机制做大」，而是先把续跑价值估计做准（也就是先解决 §4 与 §5 的瓶颈）。扩大一个机制而不改善它赖以工作的价值，只会放大噪声。

## 8. 把进化权重与精确刷新 EV 叠加

### 试了什么

四个方向并行探索之后，自然会产生「把最好的两个组合起来」的想法：进化搜索得到的冠军权重 + 精确化的刷新期望价值。

### 测到了什么

| 方向 | 平均句数 | 提升 |
|---|---:|---:|
| 进化搜索学权重 | **149.92** | +19.2% |
| 状态价值函数 | 138.27 | +9.9% |
| 刷新 EV 精确化 | 135.15 | +7.5% |
| 前瞻搜索 | 129.97 | +1.95% |
| **进化权重 + EV 刷新（叠加）** | **137** | **退步**（相对 149.92） |

（手调基线 125.76。同样是当时另一个模拟环境的口径。）

### 为什么失败

因为**进化冠军内部已经是自洽的**。进化搜索不是独立地调了 13 个旋钮，而是在同一目标下同时移动它们：押韵加分被推到绝对主导、中间态被清零、保命线与收益闸被重排。当另一套机制（精确 EV 刷新）插进来时，它假设的权衡关系与冠军已经收敛到的那套不一致，于是把已经调平的配合打散了。

这条结论在后来被更细的规则级消融进一步印证（δ 恒等式，400 局/状态逐状态精确计算）：

| 规则级消融 | 平均 Δ诗意 | 显著状态数 |
|---|---:|---|
| 关掉换组/目标大组权重 | **−0.83** | 24 个状态里 14 个显著变差、1 个显著变好 |
| 关掉诗人首收加分 | −0.01 ± 0.00 | 0 个显著变化 |
| 出韵的**评分惩罚**置 0 | **+0.42** | 16 个显著变好、0 个变差 |

读法：换组逻辑不是损失来源而是**净收益来源**（关掉会变差）；诗人首收加分这个维度**基本无效**；而出韵惩罚**略有过重**（关掉反而好一点点）。——注意这些结论描述的是**旧的三段硬门控路径**。同一次归因还测到：部署策略与精确最优的差距里，**约 68.9% 来自「最优候选出韵 → 必刷」这条硬规则**（精确最优常常是「接受这个出韵」），约 17.1% 是反向时机错误（该刷时没刷，主要是把中间态接了下来），选句质量类合计约 14%。这正是后来用「精确一步最优停止」整体替换门控的动机。

### 这意味着什么

- **各方向不是可以自由叠加的积木。** 「A 有效 + B 有效 ⇒ A+B 更好」在本问题上不成立，因为各方向都在同一个自洽解上做局部改动。
- 任何叠加都必须重新做完整的配对评测，并重新检查基线口径。踩过一次之后，这条应该成为默认纪律。

## 9. 被预算截断的搜索结果被永久缓存

这是一条**审计发现的真实 bug**，不是统计问题。它出现的形态很难自己暴露，所以单独列出来。

### 试了什么

训练流水线为了省掉重复计算，把 `TrainContinuation` 的结果按指纹缓存到磁盘，命中即复用。指纹覆盖了状态、规则、词库、选项、策略的全部字段。

### 机制（为什么截断的结果会被判定为「可缓存」）

失败链条有四环，缺一不可：

1. `TrainContinuation` 把时间预算的 **2/3 给搜索**（剩下给验证）；
2. 搜索被 `searchCtx` 截断时，循环只是 `break`，**不返回错误**；
3. 随后用**还没过期的外层 `ctx`** 跑完整验证 → 验证跑满、`err == nil`；
4. 写入条件 `cacheableTraining` 接受 `Generations > 0 && Generations <= opt.Generations`，也就是**只要求「至少完成了 1 代」，不要求跑满**；而读取路径**从来不拿 `r.Generations` 与 `opt.Generations` 比对**。

于是「跑了 6 代」和「跑了 24 代」在缓存键里**完全无法区分**（键里只有请求的 `Budget`，线上恒为 60s），一次残缺搜索会被写进缓存，并在之后**每一个相同指纹的调用**上返回。

### 测到了什么

请求 24 代、population 24、每代 256 局、验证 4096：

| 预算 | 实际完成代数 | 验证 | `Accepted` | delta | se | 满足写入条件？ |
|---|---|---:|---|---:|---:|---|
| 0（固定工作量） | **24 / 24** | 4096 | true | 94.746 | 2.040 | 是 |
| **8 s** | **6 / 24** | 4096 | **true** | **95.863** | 2.038 | **是** |
| 4 s / 2s | 未产出（搜索与验证都超时） | — | — | — | — | 否 |

8 秒那次**只跑了 25% 的搜索**（6/24 代），却完全满足缓存写入条件，`Accepted = true`、`delta = 95.863 > 2.4×SE`。触发条件也测了：固定工作量 24 代需要 19.07 s，而线上预算是 60 s，约 3 倍余量 ⇒ 需要机器慢 3 倍以上、或把代数/种群调大才会发生（确实存在一份 47 代的产物）。所以这是「**可触发但需要条件**」的缺陷，不是必然发生。

顺带发现的两个相关弱点：

- 缓存指纹对**代码语义**只有一个手写常量（无代码哈希）。改语义忘 bump 版本号 ⇒ 静默复用旧策略。
- 缓存条目只存「key + result」，不存对应的 `WorldStart` / `TrainingOptions`，所以事后**无法审计一次命中的合法性**——这也是本次审计唯一没能直接验证的环节。

### 修复

1. **写入条件改为「实际完成的代数 == 请求的代数」**；读取路径同样校验 `r.Generations == opt.Generations`，不一致就当未命中。
2. **bump 缓存版本号**，让所有既有条目失效（否则修了判定也救不回已经写坏的那批）。
3. 把 `WorldStart` / `TrainingOptions` / 词库哈希一并存进条目，让每一次命中都可事后审计。
4. 搜索被截断时应当**显式标记为不完整**，而不是靠调用方去比对代数。

### 这意味着什么

- 带时间预算的搜索 + 持久化缓存是一个**危险组合**：截断是「正常的运行时事件」，而缓存写入判定却只检查「有没有做过任何搜索」。任何把二者放在一起的实现都必须把「完成度」写进缓存键或写入条件。
- 本仓库当前**不含缓存层**，所以这个 bug 不会在此复现。但 `TrainContinuation` 保留了同一结构：搜索被 `searchCtx` 截断后，外层 `ctx` 仍能跑完验证，`err == nil`、`Generations < 请求代数`、`Accepted` 仍可能为 true。**上层若基于它加缓存或落盘，必须自己校验完成度。** 见 [algorithm.md](algorithm.md#7-traincontinuation权重向量的短程进化搜索)。

## 10. 方法论警告

这一节的每一条都来自对上面那批实验的**事后重算**，它们共同决定了「什么样的结论可以写下来」。

### 10.1 ±2SE 只覆盖一个条件维度，会低估 12~32 倍

配对 SE 是诚实的：它算的确实是「同一个起始状态下重复抽样的噪声」。问题在于它**不含状态间方差**，而引用它的人会把它当成效应量的总不确定性。

生产缓存里三条真实记录（同一流程、同一默认种子、**不同实际状态**）报出的效应量：

| 状态指纹 | 代数 | 验证局数 | 效应量（诗意） | 同一次报出的 ±2SE |
|---|---:|---:|---:|---:|
| `ece63aae…` | 24 | 4096 | **+104.83** | ±4.22 |
| `729c16cd…` | 24 | 4096 | **+102.01** | ±2.81 |
| `0079ce3f…` | 24 | 4096 | **+18.83** | ±1.52 |

均值 75.22，**跨状态 sd(n−1) = 48.86**，极差 85.99。同一个流程报出的效应量在状态之间相差约 86 诗意，而每次附带的 ±2SE 只有 1.5~4.2 —— **把 ±2SE 当作该效应量的不确定性，低估约 12~32 倍**。

配套的事实：那一批 `set-*` 评测全部是 `mixed=false` + 同一个快照，所以「1000 局」其实是**同一个状态的 1000 次抽样**，报出的 ±0.275 是「同状态重复抽样」的标准误。

**纪律**：报 ±2SE 时必须同时写清「这是几个状态」。只有一个状态时，说「该状态内」而不是「总体上」。

### 10.2 比较了很多次，所以孤立的 t≈2 不能信

整批实验里可重算的检验端点共 **58 个**（44 个句数 + 14 个诗意）。`p < 0.05` 的有：句数 28 个、诗意 2 个。Bonferroni 门槛 α = 0.05/58 = **0.00086**（|z| > 3.33）；只看那 14 个诗意端点也要 |z| > 2.91。

结果：**唯一为正且显著的诗意端点 z = 2.757（p = 0.0058）通不过**任何一个修正门槛。

**纪律**：主结论的效应量 t 在 6~12 这个量级才值得当成结论；表格里 |t| < 3 的条目（尤其 n 很小的时候）只能当方向性证据。本仓库里 §6 的 t ≈ 2.17 就属于这一类——所以它被写成「方向一致但未确立」，而不是「已改进」。

### 10.3 选择偏差（winner's curse）在这里被测得**很小**，但仍要查

这是一个正面结论，值得记下来当对照组：

- 在调参种子上比较了 3 个候选：Δ = **−1.777 ± 0.279 / −1.433 ± 0.292 / +1.704 ± 0.286**。候选之间相距约 **12 SE**，说明差异是真实信号而不是噪声，**取最大值不属于噪声驱动的 winner's curse**。
- 被选中的候选随后在**从未用于任何选择的预留种子**上重测：**+1.755，95% CI [1.217, 2.293]**。
- dev → 预留的收缩只有 **1.755 − 1.704 = 0.051 局**（占效应量的 2.9%），远小于 SE（≈0.40）⇒ **在这一个快照上测不到选择偏差。**

而且训练流程本身的门槛设计是规范的：搜索流与验证流不同源，选择在搜索流、报分在独立验证流，所以验证流上的 delta 对被选项是无偏的；门槛 `2.4×SE` 对应 3 次比较的 Bonferroni 门槛（`z_{0.025/3} = 2.394`）。

但这条对比**不能外推**：参考臂是上一个实验模型，不是发布基线。而且「本次没测到收缩」不等于「以后也不会」。

### 10.4 参考臂必须写清，否则同一个改动能变一个量级

同一个模型、同一个预留种子、同一条命令，**只换参考臂**：

| 参考臂 | Δ | 95% CI |
|---|---:|---|
| critic v2（实验模型） | **+1.755** | [1.217, 2.293] |
| 裸启发式（漏写 `-reference_critic`，参考臂没跑任何规划器） | **+14.405** | [13.777, 15.033] |

候选臂的均值完全一样（35.891）。「+1.755 还是 +14.405」纯粹取决于参考臂是谁。

**纪律**：任何「提升 X」都要写成「相对谁提升 X」。这条也和 §10.2 联动——把 +14.405 当成 learning 的功劳，结论就是错的。

### 10.5 独立候选数要真的数一遍

「v1..v6 六个模型」实际只有约 **4 次独立尝试**：v4/v6 的状态集完全相同（只改了标签抽样数），v4/v5 是同一次训练的两个 checkpoint。同样地，一批「三个变体」的 pilot 用的是同一个种子、同一批 200 局，彼此之间配对可比，但「挑最好的那个报区间」就是选择。

**纪律**：报「N 个候选里挑出最好的」之前，先数清有几个是真正独立的（独立的数据/状态/种子），否则选择压力会被高估一倍。

### 10.6 一句话清单

- 报 ±2SE 时，说明它只覆盖**几个状态**。
- 孤立 t ≈ 2 的结果不要相信；主结论要 t 在 6~12 量级。
- 任何「提升」都要写明**参考臂**与**目标口径**（句数还是诗意）。
- 留出集要用**没用过的种子**和**没用过的池**。
- 局部可证的修复（终局修复那种）不等于整局收益。
- 预测指标（MSE / label regret）变好**不蕴含**策略变强。
- 有效应就要数独立尝试数；有选择就要量收缩。
