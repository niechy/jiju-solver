# 来时路 —— 研究与失败记录

这里放的是这个算法**怎么被研究出来的**：做过的实验、量到的数字、以及没走通的那些路。

[`../failures.md`](../failures.md) 是结论（每个失败案例一段"试了什么→测到什么→为什么失败→意味着什么"）；
本目录是**原始材料**，用来让那些数字可被复现、可被质疑。

## 报告

| 文件 | 内容 |
|---|---|
| [headroom.md](headroom.md) | 用精确解量"当前策略离最优还差多少"，并把差距按来源归因。核心发现：**68.9% 的损失来自"出韵必刷"这条硬规则** |
| [policy.md](policy.md) | 决策表示的对照实验。核心发现：**精确一步最优停止**比三段硬门控规则高 **+56.58 ± 9.64 诗意**（n=600，两个留出种子），而加非线性特征检测不到增益 |
| [eval_audit.md](eval_audit.md) | 对上述评测本身的审计。发现三处会反转结论的问题，以及一个真 bug（预算截断的搜索被永久缓存） |

## 证据

`evidence/` 里是支撑关键数字的原始结果 JSON，由 `cmd/research/` 下的工具产出。

| 文件 | 对应结论 |
|---|---|
| `ab-exactstop.json` | 精确最优停止 vs 三段门控，n=200 / seed 42，诗意 +54.725 CI95 [38.561, 70.889] |

## 复现

```bash
# 与最优值的差距 + 损失归因
go run ./cmd/research/headroom -h

# 决策表示对照（精确最优停止 / 两步 / 非线性特征）
go run ./cmd/research/policy -h
```

这两个工具用 `-h` 看参数。它们默认读 `data/verses.json` 与一个池子快照，
对照实验两边共用同一批局种子，输出配对差值与其标准误。

## 两点提醒

1. **报告里的 ±2SE 只含状态内抽样噪声。** 审计发现跨状态标准差可达 48.86，
   引用 ±2SE 会把不确定性低估 12～32 倍。要看结论请连同"这只是一个池子/一批状态"一起看。
2. **做了很多次比较。** 单独一个 t≈2 的结果不足以判定（本项目累计过 58 个端点，
   Bonferroni 阈值要 |z|>3.33）。`eval_audit.md` 里对这一点有逐条清点。

这两条不是免责声明，是**这些数字该怎么读**的说明书。
